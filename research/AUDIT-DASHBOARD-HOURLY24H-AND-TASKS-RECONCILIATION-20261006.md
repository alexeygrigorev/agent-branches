### 2.1 Half-Open `[as_of-24h, as_of)` UTC Accounting Window

The contract specifies a strict half-open UTC window `[as_of - 24h, as_of)`.

- **Recorded in JSON**:
  - `as_of_utc`: `"2026-10-06T09:35:08.665140+00:00"`
  - `window_half_open`: `"[2026-10-05T09:35:08.665140+00:00, 2026-10-06T09:35:08.665140+00:00)"`
  - `hourly_buckets_count`: 24
- **Code Audit in `hourly.py`**:
  ```python
  def generate_hourly_buckets(as_of: datetime.datetime) -> List[Interval]:
      as_of = _as_utc(as_of)
      window_start = as_of - datetime.timedelta(hours=24)
      buckets: List[Interval] = []
      for i in range(24):
          b_start = window_start + datetime.timedelta(hours=i)
          b_end = window_start + datetime.timedelta(hours=i + 1)
          buckets.append((b_start, b_end))
      return buckets
  ```
- **Filter Audit in `accounting.py` (lines 299–300)**:
  ```python
  if ts < window_start or ts >= window_end:
      continue
  ```
- **Auditor Verification**:
  1. The window start is exactly 24 hours prior to `as_of` to the microsecond.
  2. Bucket boundaries are strictly half-open: `ts >= window_start and ts < window_end`.
  3. Events exactly at `as_of` are excluded from the current window (belong to the subsequent window).
  4. Non-hour `as_of` timestamps are preserved without rounding or synthetic extrapolation.
  **Verdict**: **PASS**.

### 2.2 Deduplication & Span Clipping to `min(duration, 1.0h)`

- **Provenance & Deduplication Audit (`accounting.py`)**:
  - Lines 296–298 enforce provenance tracking: records lacking `session_uuid` or `device_id` are rejected from windowed aggregation (`missing_provenance += 1`).
  - Lines 324–337 enforce response deduplication: records with `response_id` are deduplicated on `(provider, conversation_id, response_id)`. Cumulative mode records retain only the latest timestamp per `(provider, conversation_id)`.
- **Span Clipping Audit (`hourly.py`, lines 148–164)**:
  ```python
  for agent, ivals in agent_intervals.items():
      clipped: List[Interval] = []
      for s, e in ivals:
          overlap_start = max(s, b_start)
          overlap_end = min(e, b_end)
          if overlap_end > overlap_start:
              clipped.append((overlap_start, overlap_end))
      bucket_seconds = union_seconds(clipped)
      if bucket_seconds > 0:
          active += 1
          hours += bucket_seconds / 3600.0
  ```
- **Auditor Mathematical Proof**:
  For any bucket `[b_start, b_end]`, `b_end - b_start = 3600.0` seconds. For any agent span `[s, e]`, `overlap_start >= b_start` and `overlap_end <= b_end`. Therefore:
  $$\text{duration}(\text{overlap}) = \text{overlap\_end} - \text{overlap\_start} \le b\_end - b\_start = 3600.0 \text{ s} = 1.0\text{ h}$$
  Because `union_seconds` computes the Lebesgue measure of the union of intervals, duplicate spans or multiple tasks for the same agent cannot exceed the bucket width of 1.0 hour.
  **Verdict**: **PASS**.

### 2.3 Explicit Unknown Intervals vs Zero-Filling
